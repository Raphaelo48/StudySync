# RUNBOOK: полный порядок запуска StudySync

Документ описывает запуск от «пустой машины» до установленной сборки.
Все команды выполняются из корня проекта (`studysync/`).

---

## Шаг 0. Требования к окружению

| Компонент | Минимум | Проверка |
|---|---|---|
| Node.js | 20.x | `node --version` |
| npm | 10.x | `npm --version` |
| Git | любой (опционально) | `git --version` |
| Android-эмулятор | Android Studio + AVD (API 34+) | — |
| iOS-симулятор | macOS + Xcode 16+ | `xcodebuild -version` |
| Сборка APK/IPA | аккаунт Expo (бесплатный) + eas-cli | `eas --version` |

Без Android Studio/Xcode приложение всё равно можно запустить на реальном телефоне
через **Expo Go** (пункт 3.1) — компиляторы не нужны.

## Шаг 1. Установка зависимостей

```bash
cd studysync
npm install          # или: npm ci (чистая установка по package-lock.json)
```

Ожидаемый результат: `added N packages` без ошибок `ERESOLVE`.
Если `ERESOLVE` всё же появился — в проекте есть `.npmrc` с `legacy-peer-deps=true`,
он применяется автоматически; не удаляйте его.

Контроль целостности установки (опционально, ~40 c):

```bash
npm run typecheck    # 0 ошибок TypeScript
npm test             # 193/193 теста
```

## Шаг 2. Запуск dev-сервера

```bash
npm start
```

В терминале появится меню Expo (QR-код, адрес `exp://192.168.x.x:8081`).
Горячие клавиши меню: `a` — Android, `i` — iOS, `w` — веб, `j` — дебаггер,
`?` — справка, `Ctrl+C` — остановка.

Сервер держите запущенным в отдельном терминале на всё время разработки.

## Шаг 3. Запуск приложения

### 3.1. Реальный телефон через Expo Go (самый быстрый путь)

1. Установите **Expo Go** из Google Play / App Store.
2. Телефон и компьютер — в одной Wi-Fi-сети.
3. `npm start` → отсканируйте QR: Android — камерой или прямо в Expo Go,
   iOS — приложением «Камера».
4. Бандл загрузится (~10–30 с в первый раз), откроется экран первоначальной настройки.

Если QR не открывается (разные сети/корпоративный Wi-Fi):

```bash
npx expo start --tunnel     # туннель через интернет, работает везде
```

### 3.2. Android-эмулятор

1. Android Studio → Device Manager → создать AVD (рекомендуется API 34+, образ с Google APIs).
2. Запустить эмулятор.
3. В терминале проекта: `npm run android` (или клавиша `a` в меню Expo).
   Expo Go установится на эмулятор автоматически.

### 3.3. iOS-симулятор (только macOS)

1. Установите Xcode и выполните один раз: `sudo xcodebuild -license accept`.
2. `npm run ios` (или клавиша `i` в меню Expo) — симулятор откроется сам.

### 3.4. Веб-превью

```bash
npm run web
```

Ограничения веба: локальные уведомления и системный шеринг файла недоступны —
приложение показывает об этом понятное сообщение, остальной функционал работает.

## Шаг 4. Первый запуск приложения

1. Экран «StudySync» — первоначальная настройка: имя (необязательно), тема.
   Кнопка «Пропустить настройку» тоже допустима.
2. Открывается вкладка «Главная» с пустым состоянием: предложено добавить
   предмет, занятие или задачу.
3. Данные создаются локально в SQLite устройства и переживают закрытие приложения.
4. Полный сброс: Профиль → Данные → «Удалить все данные» (двойное подтверждение,
   автоматически создаётся внутренняя резервная копия с возможностью восстановления).

## Шаг 5. Повседневная разработка

```bash
npm start            # сервер
# правите код → приложение перезагружается само (Fast Refresh)
npm test             # прогон тестов после изменений логики
npm run typecheck    # контроль типов
npx expo start -c    # запуск со сбросом кэша Metro, если бандл «залип»
npx expo-doctor      # диагностика конфигурации проекта
```

## Шаг 6. Установочные сборки (без dev-сервера)

### 6.1. Локальная проверка бандла (без аккаунта Expo)

```bash
npx expo export --platform android    # Hermes-бандл в dist/
npx expo export --platform ios
```

### 6.2. EAS Build (APK / IPA)

```bash
npm install -g eas-cli
eas login                              # бесплатный аккаунт expo.dev
eas build --platform android --profile preview    # → ссылка на APK
eas build --platform android --profile production # → AAB для Google Play
eas build --platform ios --profile production     # → TestFlight
```

Профили описаны в `eas.json` (`preview` = внутренний APK, `production` = стор).
Скачанный APK ставится на телефон обычным способом (`adb install app.apk`
или открытие файла на устройстве).

### 6.3. Dev-клиент (опционально, для нативных модулей без Expo Go)

```bash
eas build --platform android --profile development
# установить APK, затем: npx expo start --dev-client
```

## Шаг 7. Типовые проблемы и решения

| Симптом | Решение |
|---|---|
| `ERESOLVE` при `npm install` | убедиться, что `.npmrc` на месте; либо `npm install --legacy-peer-deps` |
| QR не открывается / «Network request failed» | одна сеть Wi-Fi; или `npx expo start --tunnel`; или в Expo Go ввести адрес вручную |
| Порт 8081 занят | `npx expo start --port 8099` |
| Белый экран после обновления кода | `npx expo start -c` (сброс кэша), в приложении — встряхивание → Reload |
| Уведомления не приходят | Профиль → Уведомления: статус разрешения; на Android 13+ разрешение запрашивается при первом включении; режимы «Не беспокоить»/энергосбережения ОС могут откладывать доставку |
| Ошибка «Не удалось открыть базу данных» при старте | сообщить текст ошибки из красного экрана — он безопасен (без пользовательских данных) |
| Тесты падают на `expo-sqlite` в Node | тесты используют SQL.js-драйвер автоматически; нативная сборка better-sqlite3 не требуется |
| Красный экран при старте в Expo Go на Android: `expo-notifications: Android Push notifications ... removed from Expo Go` | Это side-effect модуля `DevicePushTokenAutoRegistration.fx` самой библиотеки (регистрирует push-токен при импорте). StudySync использует только локальные уведомления, поэтому модуль заглушен в `metro.config.js`. Обновите файл `metro.config.js` из репозитория и перезапустите сервер со сбросом кэша: `npx expo start -c` |

## Шаг 8. Остановка

- Dev-сервер: `Ctrl+C` в его терминале.
- Приложение на устройстве: обычное закрытие; состояние таймера и данные сохраняются.
